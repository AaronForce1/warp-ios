# Warp iOS verification and engineering check contract — draft

**Status:** Planned; no app commands, test runner or analyser configuration exists yet. The [MVP plan](phases/mvp.md#p0--resolve-executable-platform-and-contract-feasibility) assigns selection/configuration to P0.6 and carries required evidence into each delivery phase.
**Authority:** This contract derives from [user requirements](specs/product-foundation.md), [design](design.md) and the [bundled verification policy](../.claude/skills/_shared/verification-policy.md). It does not waive a required applicable tool. Actual native build/device/live-service capabilities are not available or validated in this Linux planning machine.

Biome, dependency-cruiser and React Doctor apply if their JavaScript/TypeScript/React scopes are actually introduced. A Swift app has no React/web scope merely because a release CLI is Expo-branded. If native/Expo tooling introduces authored JS/TS or React code, assess and configure the corresponding required checks for that actual code; do not classify them away by naming the overall app native. Native UI journeys use native test evidence rather than an unrelated Playwright browser suite.

## Execution and review integrity

Pin dependency/tool versions when selected, retain lock/config files, and record meaningful changes to checks. Gate suppression, assertions, exclusions, rule severity or thresholds require review against the original obligation; they cannot be weakened by a worker to obtain a pass. Required unavailable/failed checks remain incomplete, with an explicit exception only under applicable human authority.

Every obtained result identifies the actual source snapshot, command or inspection method, result and relevant artifacts/coverage limits. Review distinguishes independent review, agent self-review, human inspection and unperformed checks. Integration rechecks evidence affected by the combined source state; avoid rerunning unaffected checks without reason.

Store/release credentials, API keys and SSH private keys/passwords are never printed or embedded in docs/logs. Native credential-store access and host trust are implemented through their supported APIs. Provider/terminal content is untrusted data and does not grant execution authority.

## Evidence ownership and locations

Codex, or the named phase coordinator in a later authorized run, owns each phase's source/evidence reconciliation. Store concise source-linked results under `docs/evidence/P<phase>-<scope>.md` when evidence is actually obtained; large/raw logs may remain in the execution workspace with accessible artifact references. Do not create placeholder passing reports. A report records the exact source revision/dirty state, affected design elements, observed source/view extraction or inspection method, missing/extra/changed relationships, performed checks and their limits. The task IDs in the phase plan own the combined boundary evidence.

P0.6 configures these paths and commands before their phase gates are claimed as configured. P0.5 performs the documentary handoff under current planning authority. Prototype app/host code and executable tool setup require their later authorized execution scope; no test artifact is manufactured to advance the document's status.
