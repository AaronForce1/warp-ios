# Warp iOS domain glossary

These terms keep product discussion distinct from implementation. Requirements live in the [product foundation](specs/product-foundation.md); delivery state lives in the [roadmap](ROADMAP.md).

| Term | Meaning and agreement boundary |
|---|---|
| Terminal | The interactive input/output experience in the iOS app, connected to the remote shell in MVP. It is broader than a screen showing a command response. Exact desktop-compatibility acceptance remains open. |
| Remote host | A user-supplied server/computer accessed directly over supported password/key SSH. The host supplies its OS, shell, tools and permissions; connecting does not convert it into Debian. |
| Prepared host | A host with the app's required capabilities established through the repository setup mechanism and readiness checks. The exact capability/platform contract still needs definition. Successful SSH authentication alone is insufficient. |
| Persistent session | A named remote terminal/process context identified independently of the app connection. It should survive client interruption while the required host/session infrastructure remains alive. Host-reboot recovery is not yet agreed. |
| Connection | A live device-to-host transport attachment. Losing a connection is distinct from ending the remote session. |
| Agent | The phone-owned coordinator of conversation, model requests, approvals and terminal actions. It is not the model-provider service or a host-owned autonomous runner in MVP. |
| Model inference | Responses generated by the selected BYOK provider. Phone-owned coordination does not imply that model inference occurs offline on the phone. |
| Task | A user-directed agent objective that can contain multiple commands. Boundaries of approval, manual takeover, cancellation and concurrency still require an acceptance contract. |
| Approval mode | The user-selected task-level or per-command execution control. The two modes are agreed; their detailed lifecycle is not yet fully defined. |
| App-data sync | Account-specific iCloud synchronization of saved hosts, settings, session identities and agent conversations/history. It does not transfer a live connection or automatically execute replicated commands. |
| Credential sync | iCloud Keychain synchronization of SSH credentials and model-provider keys. It is agreed MVP scope and uses a separate mechanism from app-data sync. |
| Desktop parity | The user's capability goal and iTerm reference. The supported terminal behaviours, limits and representative acceptance suite still need to be defined; this is not an established promise to reproduce every desktop OS capability. |
| Debian/Ubuntu baseline | The user's minimum Linux CLI environment reference for repository provisioning. Exact image/release/tool/permission acceptance remains to be defined; arbitrary existing hosts retain their own environment. |
| Continuing agent work | New coordination can continue only while the phone has execution time and required connectivity. Already-running remote commands can survive independently. The visible pause/resume/control contract still needs definition. |
